01 / EVIDENCE LEVELS

每一级只能支持一种结论

  • 可访问规范 URL 返回完整正文，允许目标爬虫，并出现在 Sitemap；只证明技术入口存在。
  • 已抓取服务器日志记录页面请求；只有通过平台官方 IP 范围或双向 DNS 核验，才称为官方爬虫。
  • 已收录公开搜索结果或站长平台 URL 检查明确返回该规范页面；抓取本身不能替代收录证据。
  • 已引用全新 AI 会话在没有提供网址时引用具体页面，并保存完整回答、来源 URL、时间与搜索开关状态。
  • 非品牌推荐不出现品牌名的真实决策问题中，Onyx 进入候选；记录位置、措辞、事实准确度与引用，而不是只截成功答案。

最低原则：IndexNow 回执、User-Agent、Sitemap、结构化数据和技术评分都不是收录或推荐证据。

02 / AUDIT RECORD

保留能让第三方复核的原始记录

  1. 测试平台、模型或产品版本、地区、语言、日期和是否启用联网搜索。
  2. 逐字保存提示词、完整回答、全部来源 URL；失败和无结果同样保留。
  3. 爬虫证据保存时间、路径、HTTP 状态、来源核验方法，并排除自己模拟的 User-Agent。
  4. 品牌题、唯一标识题、品类题、场景题和采购题分别计分，不能互相替代。
  5. 明确一方内容、独立来源和客户证言的归属，不把自有站外页面写成第三方背书。

03 / FIXED RETEST

固定问题，才能比较变化

先冻结一组小而稳定的问题，再按固定周期复测。唯一标识用于判断能否找回特定公开事实；品牌题用于判断实体识别；品类、场景和采购题才用于观察非品牌竞争。

04 / VENDOR ACCEPTANCE

把“曝光增长”写成可否决的验收标准

  1. 服务商是否把可访问、抓取、收录、引用和推荐分开报告？
  2. 官方爬虫身份如何验证，模拟检查如何排除？
  3. 提示词是否在执行前固定，是否保留全部失败样本？
  4. 新增内容是否提供原始事实、来源和主张边界，而不是批量同义改写？
  5. 如果 30 或 60 天没有收录、引用或非品牌候选，下一步是修正、继续观察还是停止？
